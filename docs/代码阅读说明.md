# 代码阅读顺序

两版保留原启动文件，内部使用同一个 NMPCC 核心。建议沿一次实验的执行顺序阅读：

| 顺序 | 文件 | 功能 |
| --- | --- | --- |
| 1 | `exp2_nmpcc_latest.py` / `exp2_nmpcc_latest_grasp_pose.py` | 选择场景并启动 |
| 2 | `experiments/cli.py` | 命令行、输出路径、控制器构造和收尾 |
| 3 | `experiments/scene.py`、`experiments/scenes/` | 模型、初始抓取和场景配置 |
| 4 | `experiments/reference.py` | 夹紧、保持和完整移动参考 |
| 5 | `experiments/runner.py` | 两次预热、采样、求解、施加力矩及物理步 |
| 6 | `nmpcc/controller.py` | 反馈锚定、载荷残差、初值和失败重建 |
| 7 | `nmpcc/model.py`、`ocp.py` | 动力学、协同残差、权重、约束及缓存 |
| 8 | `experiments/recording.py`、`experiments/legacy/` | 接收公开求解结果，保持日志和图像格式 |

`nmpcc/data.py` 定义关节状态、动力学采样、接触测量、参考和求解结果。
`nmpcc/config.py` 区分固定结构配置与每拍可选参数。
`nmpcc/parameters.py` 是唯一知道扁平参数槽位的模块，实验代码不拼接大数组。
`legacy/` 是历史输出格式的边界，不含另一套求解器。

| 数据对象 | 主要字段与维度 |
| --- | --- |
| `JointState` | `q`、`dq` 各为两臂 × 7 关节 |
| `DynamicsSnapshot` | 每臂 7×7 惯性、7 维重力和阻尼、同拍接触测量 |
| `ContactMeasurement` | 法向幅值、世界力、两种力矩口径及关节载荷，各字段有独立名称 |
| `ReferenceHorizon` | 节点时间和每节点两臂各 6 维位置、速度、力及力导数 |
| `SolveResult` | 当前力矩、全部预测状态/控制、状态码、耗时和失败快照 |

控制循环的核心调用现在可以直接按含义阅读：

```python
state, dynamics = sample_current(scene)
references = reference.horizon(t, controller.node_times)
solved = controller.solve(state, dynamics, references, options)
command = solved.torque
```

位置前三维为世界坐标米，姿态后三维为旋转向量弧度；
速度对应米/秒和弧度/秒，力为牛顿，力矩为牛顿米。
所有双臂数据按控制器左、右顺序，手持版的物理臂映射在场景模块完成。

一次控制更新使用同次测量的惯性、重力、阻尼和接触载荷，在预测期间冻结；
参考按未来节点时间计算。默认 10 段有 11 个状态节点和 10 个控制节点，
终端状态也参与初始化和热启动保存。

启动先计算预测模型的平衡力矩作为初值，再预热两次；预热不推进物理时间。
模型平衡不等于真实接触已经平衡，箱体运动由 MuJoCo 更新。
控制每 6 ms 更新，物理步为 2 ms，两次控制更新之间保持力矩。

日志接收 `SolveResult`，不读取控制器私有热启动或底层求解器字段。
诊断工具在 `diagnostics/`，其中测量和关节限位记录供主循环使用。
旧源码位于 `_archive_20261009/refactor_before/`，不应继续向旧求解文件添加功能。
两版反馈口径和几何差异见 `两版配置与测量差异.md`。
